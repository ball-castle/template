## 检查范围与方法

- 全部 32 个正式模块：P0 17 个、P1 13 个、P2 2 个；逐一核对 `notes/modules/*.json` 与对应源码。根目录 32 个历史 `.cpp` 不作为正式可用版本。
- 三套驱动：`tests/test_core_data.cpp`、`tests/test_graph.cpp`、`tests/test_dp_math_string.cpp`。检查边界用例、固定种子随机对照及其独立性，而非仅依据编译成功作结论。

- 检查 `scripts/run_tests.py`、`build_notebooks.py`、`check_print.py`、`build_index.py`；随后核读新增的 PDF 导出绑定、测试入口与哈希门禁。

随机对照主要采用朴素数组操作、子集/排列/物品数量枚举、全部相邻合并次序、Floyd、逐级父亲、逐边删除后的可达性，以及直接字符串比较，能够独立检查相应实现。特别复核了 Hamilton 的缺边与负权、乘积递推的零底数和指数约减、迭代 SCC 的退出顺序，以及找桥时按边编号跳过父边。

## 发现并已关闭的问题

1. **评审严重度 P2：旧 PDF 在页数不变时可误过打印门禁。** 原 `check_print.py` 只比较源码、manifest 与 DOCX 的代码文字；PDF 仅检查页数、纸型和预期页面上的模块编号。复现方式是保留旧 PDF，修改源码并重跑测试、重建 DOCX，同时保持分页和模块编号不变，但跳过 PDF 导出；原检查仍可能返回通过，交付的 PDF 却不是当前代码。

   修复后，[check_print.py](../../scripts/check_print.py) 要求导出绑定文件同时匹配当前 DOCX 与 PDF 的 SHA256。Word 导出成功并关闭文件后由 [export_word.ps1](../../scripts/export_word.ps1) 写入绑定；[export_pdf.py](../../scripts/export_pdf.py) 提供跨平台入口。[test_print_gate.py](../../tests/test_print_gate.py) 保留同页数旧 PDF 的回归用例。主流程已复现修复前失败、修复后通过，并完成最终配对门禁；本审查核读了修复逻辑，没有重复运行该流程。

2. **低风险验证建议：声明的功能测试必须实际执行，并绑定其源码版本。** 原测试器只需找到至少一个 `test_*.cpp`，报告也只记录模块源码哈希；某个驱动缺失时，其模块可能仅通过独立编译。修复后的 [run_tests.py](../../scripts/run_tests.py) 检查每个模块声明的测试入口，确认其被执行，并记录 `test_sources`；[build_notebooks.py](../../scripts/build_notebooks.py) 同时检查模块与测试驱动哈希。当前三套驱动均有匹配证据。

3. **低风险纸面易用性建议：说明本地头文件的手抄方式。** M03/M04/M05 的本地 `#include` 在仓库工程内有效；若将依赖直接抄进同一 `.cpp`，保留该行会因缺少文件而编译失败。完整版前言现已明确要求一并抄入依赖，并在合并到同一文件时省略本地 `#include` 与 `#pragma once`，保留 `bits/stdc++.h`。

初轮提出的 DSU 空图/连通块数及 BFS 有向边界建议也已加入测试。最终审查没有新增必须补测项。
